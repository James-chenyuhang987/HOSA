# 诊途

诊途是一个面向跨方言就医沟通的 HOSA 参赛原型，帮助普通话使用者与粤语、闽南语、上海话、四川话或东北话使用者双向沟通，并提供文字、读法、语音输入和沟通提示。

## 当前功能

- **双向方言翻译**：在普通话与粤语、闽南语、上海话、四川话、东北话之间切换，获得常用表达的文字与读法。
- **就诊沟通短句**：医院场景词库包含 89 类短句、五种方言共 445 条表达，另保留原有基础短句，覆盖预约挂号、科室问路、症状描述、既往病史、过敏与怀孕、检查准备、用药询问、住院/出院和书面确认。分别收录“需要家属陪同吗”和“我需要家属陪同”，区分一般更改预约与更改预约时间；“想呕吐”不会被额外加上“恶心”。
- **带时间的医院句式**：在 11 类已收录症状上支持部分时长/开始时间句式，例如“我头痛大约三天了”“我从昨晚开始头晕”。同时支持部分完整症状、用药状态及不确定陈述的时间范围，例如“我今天没有发烧”“我今天还没有吃药”。症状时长、开始时间与时间范围分别标注，时间范围不会被误写成起病时间，也不会自动扩展到下一句。症状使用已有方言短句，时间作为书面信息单独列出；数值、单位、约数、范围、半单位、复合时长及“昨晚”等原文时间保留，例如“大约三天”“三到五天”“一天半”“1小时30分钟”，不换算或推测连续发作。支持切换方向还原含义；结果单独标注“医院句式 · 待核对”，不编造整句读音。临床否定和不确定表达须命中完整短句，不从肯定句自行拼接；未知症状、未知陈述和额外未知分句继续保留参考。医院短句库的“症状”场景提供可直接点击的带时间示例。
- **内容保真**：简繁体短句可等价匹配；语音识别常见的逐字空格、全角标点和带分隔符的句首“嗯／那个”等口头填充会在匹配时轻量归一，不改写句中医学词语。“那个药”等实词保留，换行作为分句边界。组合翻译按完整短句或明确症状句式匹配，支持方言短句内部自带逗号，只有全部内容被覆盖时才组合，不会跳过未知内容。保留问句意图，不把“不舒服”擅自改成“有点”或“很不舒服”；减少机械添加的四川话语气词，保留医保等制度名称，不按方言自动替换为其他地区制度。
- **离线优先翻译**：医院词库和高频症状、病史、检查、用药表达直接在浏览器运行，常用短句不需要你的电脑当服务器。未覆盖的整句仍可选择接入任意兼容服务；已加入 Hy-MT2、MiLMMT、Taigi 与通用模型适配，默认关闭。
- **一键整句翻译**：后端配置好后，用户点击“一键开启”即可检测服务并启用当前方言，无需填写地址或凭证。检测只请求健康状态，开启后才会发送输入文字；连接失败或当前方言没有可用模型时继续保留词库结果。其他后端地址和访问凭证仍可在折叠的“翻译设置”里配置。
- **语音输入翻译**：点击输入框旁的麦克风，用普通话或当前方言录入一句话，识别文字会自动进入翻译结果。默认使用浏览器 `SpeechRecognition`；也可以在“翻译设置”中启用 MediaRecorder + 本地 ASR。
- **手机现场沟通**：输入停顿 800ms 后自动翻译，中文输入法组词时不触发；麦克风和立即翻译集中在输入框下方。点击“查看译文”可定位结果；“立即翻译”及 Ctrl/Cmd + Enter 会立即提交并定位结果，自动翻译保留输入焦点。编辑时保留上一条结果并标明过期，确认新结果后才能复制或放大展示。
- **译文展示与短句选择**：放大展示同时显示原文和译文，可调节字号、按 Escape 关闭并恢复焦点；展示内容固定为打开时的结果，避免模型补译打断阅读，关闭后再次打开可查看新结果。读法与沟通提示按需展开，缺少读法时省略读法区域。医院短句支持八类场景、“全部”及关键词搜索，可查普通话、已收录的同义问法和当前方言，点击后立即翻译并定位结果。
- **轮流沟通**：明确选择“我说普通话”或“对方说方言”。“换对方说／换我说”和“再说一句”会保留当前结果并清空输入，避免把上一条译文当成对方的新回答。本页对话可回看、放大和编辑原文，最多保留最近 20 句，刷新即清除；“结束并清空对话”同时清除输入、结果、对话记录和翻译缓存。
- **译文朗读**：仅在设备提供明确匹配的本地普通话或粤语声音时启用，可手动停止；编辑、录音、切换结果或关闭展示时停止当前朗读。其余方言、缺少对应声音或整句尚未翻译时显示原因，提供放大展示，不用普通话冒充其他方言。声音枚举和本地标识来自浏览器 [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices) 与 [localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)。
- **医院地图**：填写医院名称、院区和可选城市后，通过[高德地图官方搜索链接](https://lbs.amap.com/api/uri-api/guide/search/search)查找真实医院；只在点击时向高德发送该处填写的名称和城市，不携带翻译文字。院内科室仍需医院官方资料。原有建筑、楼层和服务点示意收在“查看院区示意演示”中，明确标注非真实医院，不提供实时定位。

截图中的 WenetSpeech、WenetSpeech-Chuan、WenetSpeech-Yue、WenetSpeech-Wu 和 WenetSpeech-Min 是公开的普通话及方言语音语料库，不是可直接放进 GitHub Pages 的翻译接口。项目保留对应的[资源索引](src/dialectResources.ts)供后续研究；当前离线翻译由手工维护的医院词库与有限句式完成，尚未使用这些语料训练或接入语音模型。浏览器不会自动下载语料，也不会把医疗录音上传到这些仓库。

语音识别默认使用浏览器原生 `SpeechRecognition` 能力。Chrome、Edge 等浏览器支持较好，其他浏览器可能需要直接输入文字。粤语会优先请求 `zh-HK` 识别；闽南语、上海话、四川话和东北话暂使用普通话识别模型，方言口音可能影响结果。若在“连接设置”检测到已配置的本地 ASR，可打开“优先使用本地语音模型”：浏览器只负责把本次录音临时编码，音频经 HOSA 后端发送到你配置的 OpenAI Transcription 兼容接口，服务端不保存录音；关闭该选项后继续走浏览器识别。浏览器会请求麦克风权限，浏览器是否将语音交给其识别服务商处理，取决于浏览器实现和隐私政策。请先等界面显示“麦克风已打开”再开始说话；短暂静音或识别服务提前结束时，页面会自动短暂重连，并尽量保留已经听到的文字。录音开始前可取消启动，识别等待时可取消识别；设备启动超过 12 秒或结束超过 5 秒会清理会话并提示重试。采音最多 60 秒，本地临时录音最多 10MiB，达到上限会结束录音（文件超限时需缩短后重录）。识别超过 240 字时会提示分句处理；浏览器保留的前 240 字需要核对，不会直接自动翻译截断的内容。编辑或清空文字会取消当前语音会话，迟到的权限结果和识别结果不会覆盖当前输入。失败时可重新录音或改用文字输入；已开启本地语音时，也可主动选择浏览器重新录音。

翻译结果用于辅助沟通，不替代专业口译、医疗判断或医院官方信息。四川话和东北话等方言存在明显的地区差异，界面会区分“常用短句”“医院句式 · 待核对”“词语参考”“原文 · 尚未翻译”和“模型生成 · 待核对”；涉及用药、剂量和检查安排时，请让医护人员复述确认。

没有完整收录的普通句子会尝试一次性替换常见词语，优先匹配较长用词，保护已识别的药名、数字与单位，不对替换后的文字再次连锁替换。结果以“方言用词参考”为标题，明确提示“整句尚未完成翻译”，不会启用朗读。可选择医院短句或开启整句服务，涉及诊断、用药和检查安排时仍应让医护人员再次确认。

## 技术栈

- **前端框架**：React 19 + React DOM
- **开发语言**：TypeScript
- **构建工具**：Vite
- **界面样式**：原生 CSS，包含响应式布局、暖色纸张质感和 CSS 动画
- **语音识别**：浏览器原生 Web Speech API（`SpeechRecognition` / `webkitSpeechRecognition`）或 MediaRecorder + 本地 OpenAI Transcription 兼容 ASR（可选）
- **翻译逻辑**：本地医院词库优先，支持离线短句、有限症状时间句式、完整短句组合和保守的部分用词替换；未覆盖整句时可选通过 Node 后端连接 Ollama 或 OpenAI 兼容接口
- **后端**：Node.js 原生 HTTP / fetch，无数据库；OpenCC-js 用于台语模型输入的简繁字形转换
- **测试工具**：Vitest + Testing Library + jsdom，后端使用 Node 内置测试工具
- **代码检查**：Oxlint
- **部署方式**：默认发布到 GitHub Pages，基础翻译不需要 Node 后端；Node 后端仅作为可选的模型补译与本地 ASR 增强

后端对公网运行时要求 24–256 个可打印字符的 `HOSA_API_TOKEN`，拒绝空格、换行和其他控制字符；翻译 JSON 请求体限制为 8 KB、文字限制为 240 字，本地 ASR 录音默认限制为 12 MB，并按来源凭证限流，连续输错凭证也会暂时限流。`HOSA_ALLOWED_ORIGINS` 只能填写不带路径、查询参数或内嵌凭证的完整 `http/https` 来源。分享凭证保存在权限为 600 的本地文件中，不会写入 URL 或前端构建产物。

### 实现说明

- 应用包含 React 前端和可选的 Node 翻译后端。GitHub Pages 上默认使用浏览器内的方言词库与院区示意，不需要维护者的电脑在线；查找真实医院需要联网。
- 默认语音录音只在当前页面临时转换为文字，不生成、不保存音频文件，也不会由应用主动上传音频。开启本地 ASR 后，音频只发送到用户在后端配置的 ASR 地址，用于当前请求，HOSA 不写入磁盘；ASR 运行时自身的日志和缓存不由本项目控制。
- Web Speech API 是否把语音交给浏览器或其识别服务商处理，由浏览器实现和对应隐私政策决定。
- 粤语识别优先使用 `zh-HK`；闽南语、上海话、四川话和东北话使用 `zh-CN` 作为兼容回退，因此浏览器结果可能按普通话口音识别。本地 ASR 是否覆盖对应方言取决于实际部署的模型。
- 词库和翻译规则位于前端代码中，识别文本会复用同一套翻译逻辑；用户可以在翻译前编辑识别结果。
- 院区示意使用原生 SVG、CSS 与 React 交互实现；真实医院搜索通过高德外部链接打开。建筑与楼层示意数据位于 `src/hospitalMapData.ts`；提供真实院内指引前，需要用院方确认的资料替换演示数据。
- 医院词库位于 `src/hospitalLexicon.ts`，按八类场景维护；完整短句组合位于 `src/phraseTranslation.ts`，症状时长/起始时间及陈述时间范围句式位于 `src/hospitalSentencePatterns.ts`，有限时间匹配规则位于 `src/hospitalTime.ts`，匹配归一位于 `src/translationMatching.ts`。当前覆盖高频呼吸困难、胸痛、恶心、腹泻、慢病史、检查准备和住院沟通表达。OpenCC 仅用于匹配时的字形归一，不把简繁转换当成方言翻译，也不修改未覆盖的原文。短句匹配不使用模糊相似度，避免把“没有”“可能”等关键信息误匹配；即使开启模型，已完整覆盖的医院句式也在浏览器内完成。
- 新增表达为文字沟通参考，尚未完成母语者与医疗口译人员审校；科室、疾病和药物等专业名称尽量保留原义。部分表达写法可能与普通话相同，区别在读音。缺少已核对读音时省略读法区域，地区读音差异保留在沟通提示中，不自动编造读音。
- 模型适配代码位于 `server/`，权重需要自行部署。粤语路由到 Hy-MT2 / MiLMMT，闽南语路由到台湾台语模型，上海话、四川话、东北话可配置通用模型。接口连接不等于方言质量认证。
- 翻译模型只接收原始文字；只有在用户明确打开本地 ASR 时才会把当前临时录音发到配置的 ASR 地址。HOSA 后端不记录原文、译文或录音。`src/medicalLiterals.ts` 保护数字、常见单位、部分药名及相邻剂量、正式腹部/侧别部位、血压、日期和时刻；`server/translationQuality.mjs` 对已覆盖的症状检查否定/不确定关系，并检查左右部位、部分时间锚点与问句意图。未通过检查时显示可理解的提示并保留参考；这些有限规则不能保证医学语义准确，模型译文始终标记待核对。
- 前端对同一请求去重，最多缓存 20 条成功结果、有效期 5 分钟，缓存仅在当前页面内存中。更新连接配置时清空缓存；医疗文字、音频和连接凭证不写入浏览器持久存储，仅记住方言与翻译方向。
- “翻译设置”默认收起，地址与凭证编辑后点击“保存并应用”。“检测连接”使用轻量健康请求（10 秒）；“检测模型推理”单独执行短文本推理（40 秒）。“语音服务已配置”不代表已经验证识别准确率。
- 前端支持结果来源、取消与失败回退，编辑输入或切换方言会取消旧请求，避免旧结果覆盖新内容。见 [本地模型部署](docs/local-model-deployment.md)和 [翻译 API 说明](docs/translation-api-design.md)。

## 本地开发

需要 Node.js ≥ 22.18.0（建议 24+）。仅使用本地词库时：

```bash
npm install
npm run dev
```

如果需要模型补译，再另开终端运行 `npm run server`，Vite 会代理 `/api`。这一步不是普通使用的前置条件。最短的粤语模型部署路径（更高质量的 Hy-MT2 7B 也已放在示例配置中，可按机器内存手动启用）：

```bash
ollama pull hf.co/tencent/Hy-MT2-1.8B-GGUF:Q4_K_M
npm run build
npm run server
```

打开 `http://127.0.0.1:8787/HOSA/`，点击“一键开启”连接整句翻译。Ollama 需已安装并启动，其他模型及配置见 [完整部署指南](docs/local-model-deployment.md)。如果只使用 GitHub Pages，跳过本段即可。

如果以后确实需要让其他人调用你电脑上的模型，才使用 `cloudflared` 和 `npm run server:share`；这不是 GitHub Pages 的必需步骤。它会启动带访问凭证的分享后端和临时 HTTPS 隧道，模型需先在本机部署，详见[可选的电脑 API 服务器指南](docs/computer-api-server.md)。

## 质量检查

```bash
npm test
npm run lint
npm run build
git diff --check
```

已配置并启动本地模型后，可单独运行 `npm run eval:translation`。它使用 11 条固定的合成医院测试句，覆盖五种方言及部分反向翻译，检查症状、否定、时间、剂量、部位和问句；只输出这些测试句的结果，不读取真实对话。未启用的方言会跳过，存在失败或全部跳过时返回非零状态。通过数不代表方言或医学准确率，仍需母语者与医疗口译人员审校。

词汇核对参考包括[香港中文大学粤语课堂“求医”](https://www.ilc.cuhk.edu.hk/workshop/Chinese/Cantonese/OnlineTutorial/courseList_b10.aspx)、[教育部台语辞典“發燒”](https://sutian.moe.edu.tw/zh-hant/su/8751/)和[“腹”中的“腹肚疼”用例](https://sutian.moe.edu.tw/zh-hant/su/9859/)。这些资料用于核对部分词语，不代表整套医院短句已获机构审定。

## GitHub Pages 部署

Pages 直接托管静态前端，基础医院词库翻译、录音后的文字编辑和地图功能都能使用，不需要你的电脑持续开机或运行后端。只有在页面中主动开启“模型补译”并填写一个可访问的增强服务时，才会发送未覆盖的整句；不配置时会保留离线词库参考。浏览器语音识别是否使用浏览器服务商，由浏览器实现和隐私政策决定。

合并到 `main` 后，GitHub Actions 会自动构建并发布网站：

<https://james-chenyuhang987.github.io/HOSA/>

首次部署前，请在仓库的 **Settings > Pages > Build and deployment** 中将 **Source**
设置为 **GitHub Actions**。之后每次推送到 `main` 都会自动更新网页，也可以在
**Actions > Deploy to GitHub Pages** 中手动运行。
